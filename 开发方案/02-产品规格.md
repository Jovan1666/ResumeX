# ResumeX 产品规格

执行时以本文为准。`01` 是问题，`04` 是调研任务，本文是**做出来必须长什么样**。阶段 0 调研只允许改「调研锁定」里标注可改的数字/色值/8 套内的微调。

---

## 1. 产品定义

**ResumeX**：开源、免费、本地运行的中文简历制作工具。发行形态以 **Windows 桌面安装包**为主，浏览器打开同一套 UI 为辅。

- 给谁：国内校招、社招、部分体制内投递者
- 不给谁：要做欧美创意海报简历的设计师（那不是本产品默认路径）
- 不做：账号、云同步、付费模板、后端 API、手机原生 App

核心循环：选身份 → 填信息 → 右侧 A4 实时预览 → 换干净模板 → 导出 PDF/Word/PNG → （桌面）有新版本则更新。

---

## 2. 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 发行 | Electron NSIS per-user + 仍可 `npm run dev` | 用户不要装 Node；开发者仍要网页 |
| 更新 | electron-updater + GitHub Releases | 用户原话：仓库发新版软件要能感知并覆盖 |
| 存储 | IndexedDB 为主，照片单独存；失败必须可见 | localStorage 5MB + base64 会丢整库 |
| 模板数量 | 6～8，默认国内单栏 | 35 套西方风是「畸形」来源 |
| 默认模板 | 校招通用单栏（教育在前） | 现在默认 `tech` 是西方橙红 |
| 新简历 | 空个人信息 + 按身份的空模块 | 禁止再克隆李明 |
| PDF | 桌面 printToPDF；浏览器诚实降级 | 截图像素 PDF 切句、不能选字 |
| 页边距实现 | 模板自己控制；废除全局 `!important` padding | 双栏白框根因 |
| 断点 | 模板禁用视口 class | `hidden md:block` 导出丢照片 |
| 主题 | 切模板同时切 `templateThemeMap` | 现在预览骗人 |

## 3. 信息架构与路由

保持 HashRouter（Electron `file://` 必须）：

| 路由 | 页面 | 变化 |
|---|---|---|
| `#/` | 落地页 | 中文、装包/打开编辑、检查更新（桌面） |
| `#/dashboard` | 简历列表 | 触控可删除；缩略图轻量 |
| `#/editor` | 左表单 + 右 A4 | 真保存、撤销按钮、更新入口 |

404 页在 Router 内：用 `Link to="/"` 或 `navigate('/')`。禁止 `<a href="/">`，禁止 `navigate('#/')`（会变成 `#/#/`）。

`ErrorBoundary` 当前包在 `HashRouter` **外面**，不能用 `Link`/`useNavigate`。二选一：(a) 把 ErrorBoundary 移到 HashRouter 内部再使用 `Link`；(b) 边界内用 `<a href="#/">` 或 `window.location.hash = '#/'`。禁止只改成 `Link` 却不搬位置。

Electron 打开后可直接进 `#/dashboard` 或上次简历。`hasOnboarded` 可继续单独 localStorage key（与简历库分离），或进同一 idb；须在实现时写明。

## 4. 数据模型（必须改）

文件：`界面/src/app/types/resume.ts`。

### 4.1 Profile

```ts
interface ResumeProfile {
  name: string;
  title: string;          // 求职意向
  email: string;
  phone: string;
  location: string;
  website?: string;
  wechat?: string;        // 独立字段，表单分开
  avatar?: string;        // 存 blob id 或短 dataURL；禁止塞 5MB
  summary?: string;       // 自我评价
  gender?: string;
  birthYear?: string;
  politicalStatus?: string; // 体制内
  nativePlace?: string;
  customFields?: { id: string; label: string; value: string }[];
}
```

表单：基本信息里姓名/意向/电话/邮箱/城市/微信/网站/照片必能填。性别、出生年、政治面貌、籍贯放「更多信息」折叠，默认折叠。互联网岗不强制。

电话校验：去空格去 `+86` 再测；允许 `138 0000 0000` 这种输入，存储可保留用户格式或统一 11 位，校验不要对用户吼。

### 4.2 模块类型

```ts
type ModuleType =
  | 'education'
  | 'experience'   // 工作或实习，用 title 区分「工作经历」「实习经历」
  | 'projects'
  | 'campus'       // 校园经历（可仍用 custom 实现，但类型要有）
  | 'honors'
  | 'skills'
  | 'custom';
```

`summary` 继续在 profile，模板里当「自我评价」节，空则不渲染。

`visible === false` **或** `items.length === 0` **或**（评价）空字符串 → 纸面不渲染该节。

### 4.3 技能

`SkillItem`: `{ id, name, group?: string }`。删除对 `level` 百分比条的依赖。UI 用分组文本：「前端：React、TypeScript」。

### 4.4 条目日期

继续 `date` 展示字符串 + `startDate`/`endDate`。解析要兼容 ` - `、`-`、`—`、`至今`。DatePicker `isPresent` 必须派生自 `value === '至今'`。年份范围至少 1980–当前年+1。

### 4.5 简历对象

保持 `resumes: Record<id, ResumeData>` + `activeResumeId`。persist **只发一个 version：`3`**（一次 migrate 做完：localStorage 信封→idb、TemplateId 全表、ThemeColor、缺字段、自定义字段补 `id`）。禁止阶段 1 占 `version: 2`、阶段 2 仍写 `2` 导致映射不跑。

初始内存 **不要**用李明占位：`resumes: {}` + 水合门闩，hydrate 完成前禁止 persist 写盘。hydrate 失败只设 `hydrationError`，进入全屏只读恢复（导出损坏数据 / 清空后新建），Dashboard/Editor 进不去。**禁止** `onRehydrateStorage` 把 `initialResumeData` 写回存储。

迁移时读取的是 Zustand persist 信封 `{ state, version }`，不要把整段 JSON 当 `resumes`。

### 4.6 身份预设模块顺序

- 应届生：教育 → 实习 → 项目 → 校园 → 技能 → 荣誉 → 评价
- 社招：工作 → 项目 → 教育 → 技能 → 荣誉 → 评价
- 体制内：基本信息（含政治面貌）→ 教育 → 工作 → 项目/课题 → 荣誉 → 评价；不要致谢

`QuickStartWizard` 按上面走，模板 id 映射到第 5 节的新 id，禁止再指向 `creative`/`infographic`。

## 6. 编辑器体验

### 6.1 输入

- 中文 IME：`compositionstart` 期间不要 debounce 写 store
- 防抖写 store 时忽略「自己写回」的 echo（比较 local 与 incoming）
- 卸载、失焦、切模块：**必须 flush**
- 校验失败允许继续编辑和导出（导出只强制姓名）；电话红字不要用未去空格的正则

### 6.2 撤销

- 历史存**变更前**快照，或 push 前若与栈顶深比较相等则跳过（修第一次 Ctrl+Z 空操作）
- 冷却只跳过 undo 自己触发的那一次 store 更新，**不要** 2 秒吞用户输入
- 焦点在 `input/textarea/select/[contenteditable]` 时：Ctrl/Cmd+Z/Y **永远**不 `preventDefault`、不调简历 undo。简历撤销只走顶栏按钮和 Ctrl+Alt+Z（Windows）/ Ctrl+Shift+Z 在非输入焦点时。
- store 暴露 `canUndo` / `canRedo`。改的是 `UndoRedoManager` + `useResumeStore`，不是未使用的 `useUndoRedo` hook。
- 顶栏始终有撤销/重做按钮（含禁用态）
- 历史仍内存即可；刷新清空可接受，但要能用

### 6.3 保存

- persist `setItem` wrap try/catch；失败 toast「保存失败，存储空间不足，请导出备份」并打红点
- 「已保存」仅在最近一次 persist **成功**后显示；进行中显示「保存中」
- Ctrl+S：flush 输入 + 尝试 persist + 成功才 toast

### 6.4 照片

- 裁切输出 JPEG，5:7，**≤ 150KB**
- 新增 `界面/src/app/store/avatar.ts`：`saveAvatar` / `loadAvatar` / `deleteAvatar` / `cloneAvatar`
- UI 只用 `useAvatarObjectUrl(resumeId)` 得到 `blob:` URL，卸载 `revoke`。模板**禁止** `src={profile.avatar}` 当 dataURL
- `profile.avatar` 只存 key，如 `idb:avatar:<resumeId>`
- migrate：旧 dataURL 写入 idb；长度 > 20KB 的 dataURL 在 version 3 迁移时丢掉并 toast「照片请重新上传」（避免撑爆）
- `exportBackup` 必须带照片：zip（`state.json` + `avatars/<resumeId>.jpg`）。`importBackup` 先写 blob 再写 state，期间暂停 persist
- `duplicateResume` / `deleteResume` 必须 clone/delete blob
- 文件 input 选同一文件要能再触发（清空 value）

### 6.5 模板弹窗

- 最多 8 张卡；缩略图用静态预览图或一台低成本 ScaledPreview，**禁止**同时挂 35 棵真模板树
- 大预览可以懒加载当前 hover 的那一套

### 6.6 诊断

- 「去填写」要能滚到对应表单；给 BasicInfo/Module 打 `data-section` / `data-module-id`
- 电话校验与表单同一套去空格逻辑
- 适应一页与滑条最小字号一致

### 6.7 仪表盘 / 落地页

- 删除复制按钮在移动端可见
- 落地页文案与真实模板数一致；主 CTA 桌面端「开始做简历」，开发模式可保留
- 快速开始不要指向已删除模板 id

## 7. 存储架构

目标接口（名字可改，行为不能少）：

```ts
interface ResumeStorage {
  load(): Promise<PersistedState | null>;
  save(state: PersistedState): Promise<void>; // 失败 throw
  exportBackup(): Promise<Blob>;
  importBackup(file: File): Promise<void>; // 写盘+写内存原子，禁止 500ms 竞态
}
```

- Web：`idb-keyval` 或等价，库名如 `resumex-db`
- Electron：同一 IndexedDB（Chromium）；另提供「导出到文件」到 `userData/backups/`
- 从 `resume-storage` localStorage **一次性迁移**：成功后删旧 key；失败保留旧 key 并提示
- hydrate 失败：进入只读恢复屏（导出损坏数据 / 清空），**禁止**静默写李明
- `partialize`：不要把 undo 栈 persist

## 8. 导出

文件名继续 `generateExportFilename`：`姓名_求职意向_简历.ext`，非法字符剥掉。

| 格式 | 桌面 Electron | 浏览器 |
|---|---|---|
| PDF | 见下节，禁止打整窗编辑器 | `window.print`（print-mode）或明确标注的图片 PDF |
| PNG | 仍可用 html-to-image，但只截 `.resume-page` 且 scale=1 | 同 |
| Word | `docx` 国内结构：姓名+意向+联系+矩形照+各节 Heading | 同 |

导出前 flush 输入。无姓名阻止并 focus 姓名框。

PDF 分页：打印 CSS 真正打在原语 class 上（`.rx-section`、`.rx-item`）`break-inside: avoid`。

### 8.1 桌面 PDF（锁死，阶段 0 只确认英寸字段名）

**禁止**对含编辑器 chrome 的当前窗口直接 `printToPDF`（会打出左侧表单+顶栏）。

必须：进入 print-mode，只显示 `.resume-page`，`transform: scale(1)`，所有编辑器外壳加 `editor-chrome no-print`。

`print.css` **禁止** `header { display:none }`（简历里的姓名头可能是 `<header>`）。改为 `.editor-chrome { display: none !important }`。**禁止**再给 `.resume-page` 设 `padding: 0 !important` 把 `--rx-page-padding` 打掉。

`printToPDF` **不要**写 `margins: { marginType: 'none' }`（那是 `webContents.print()` 的字段）。Electron 33 形态（R4 必须打开官方文档核对后贴进 §12）：

```js
{
  pageSize: 'A4',
  printBackground: true,
  margins: { top: 0, bottom: 0, left: 0, right: 0 },
  // 若文档有 preferCSSPageSize，阶段 0b 决定是否打开
}
```

IPC 把 PDF `Buffer` 交给渲染进程另存为文件，不能把系统打印对话框当成导出成功。

## 9. 桌面端与自动更新

### 9.1 壳

- 保留 `electron/main.js` 单窗，1400×900，最小 800×600
- `preload.js` + `contextIsolation: true` + `contextBridge`
- `app.setAppUserModelId('com.resumex.app')`
- `loadFile(webapp/index.html)`；缺失则显示错误页，不要永远 `show: false`
- `will-navigate` / `setWindowOpenHandler`：http(s) 外开，拒绝 file 逃逸
- 窗口图标 `electron/icon.ico`；修复 ICO 生成不要写 512 目录项

### 9.2 构建

根 `package.json`：

- `version` 与发版 tag 同步（`1.1.0` / tag `v1.1.0`）
- `repository`: `https://github.com/Jovan1666/ResumeX.git`
- `author` 写上
- `version`: **`1.1.0`**（更新器只认根 package.json）
- 顶层 `build.artifactName` **与** `build.nsis.artifactName` 都写成 `ResumeX-Setup-${version}.${ext}`（无空格；只写顶层可能被 NSIS 默认 `` `${productName} Setup ${version}` `` 盖掉）
- `build.publish.provider`: `github`，owner `Jovan1666`，repo `ResumeX`
- `electron-updater` 放 **dependencies**
- `build-setup.js`：本地 `electron-builder --win --x64 --publish never`；CI `--publish always`。**pack 成功后再删**临时 `webapp/`。CI 用 `GITHUB_TOKEN`（contents: write）
- 验收：打开生成的 `latest.yml`，其 `path` 与 exe 文件名**逐字节一致**

### 9.3 更新 UX

- 启动后（仅 packaged）检查更新
- 顶栏或仪表盘：无更新不打扰；有更新显示「发现新版本 x.y.z」+ 发行说明摘要 + 「立即更新」
- `autoDownload = false`，点按钮再下；进度百分比
- 下完「重启并安装」→ `quitAndInstall()`
- 检查失败（无网/GitHub 被墙）：按钮「打开下载页」`https://github.com/Jovan1666/ResumeX/releases/latest`
- 开发模式 `electron .` 不检查或明确「开发模式无更新」

### 9.4 数据在更新后

NSIS 覆盖安装不碰 Chromium IndexedDB（在 userData）。不要把简历只放在安装目录。

### 9.5 关于「仓库更新了就能感到」

用户原话是仓库新版。技术上更新器只认 **GitHub Release + latest.yml**，不认每次 push。规格：**发版流程 = tag + 构建 + 上传 exe 与 latest.yml**。README 写清。可额外做「有新 commit」但那不是覆盖安装的路径，不要做假的。

旧 v1.0.0 用户没有 latest.yml，**不能**从那一版自动升上来。阶段 6 产出的安装包是新底包；之后的 1.2.0 才能热更。文档写一句。

### 9.6 CI

加 `.github/workflows/release.yml`：tag `v*` 时 windows-latest，Node 20，`界面` 与根目录装依赖，`node build-setup.js` 且 **publish**。`GH_TOKEN` permissions `contents: write`。在 GitHub 托管 runner（ASCII 路径）构建，避免 `个人工具` 中文路径坑。

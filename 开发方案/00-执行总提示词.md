## 4. 已锁定、调研也不得推翻的决策

这些是产品方向，子智能体只能帮忙填数字，不能改成西方 CV 产品：

1. 目标用户：国内求职者（校招、社招、部分体制内），不是欧美 Creative Resume。
2. 纸张永远 A4 竖版。模板组件里**禁止** `sm:` / `md:` / `lg:` 等视口断点（那会让窄窗口导出缺照片）。
3. 默认一页。校招超过一页要明确提示。禁止技能百分比条、虚荣统计（「2 份工作」）、时间线圆点轨道、大渐变波浪、英文全大写栏目名。
4. 模板从 35+ 收到 **默认 8 套**（R5 至多把 compactSplit 放进「更多」，不得加第 9 套）。西方 infographic / timeline / executive gold / creative clip-path 删除，阶段 3 结束 git 删旧 tsx。
5. 默认新简历**空白个人信息**，禁止再预填「李明 / 高级全栈工程师」。
6. 无后端。Web 用 IndexedDB（不要把带照片的整库塞进 5MB localStorage）。Electron 同样用这一套，可额外把备份文件落到 `userData`。
7. 桌面更新走 **electron-updater + GitHub Releases + NSIS**，靠 `latest.yml`，不靠 git commit，不靠 zip 覆盖正在运行的 exe。
8. 安装包文件名**不许空格**（当前 `ResumeX Setup 1.0.0.exe` 会被 GitHub 改成点号，更新器对不上）。
9. 切模板必须同时切对应主题色。
10. 全局 `fonts.css` 不得再用 `!important` 给所有模板根节点垫一层 padding（这是双栏色条到不了纸边、看起来像贴在白纸上的根因）。

调研可以改的：具体 mm/pt/hex、6～8 套各自的栏目微调、PDF 主路径（桌面 printToPDF / 浏览器 print）、IndexedDB 库名。

## 5. 视觉模型怎么用（强制）

每做一个用户可见改动：

1. 用真实国内示例数据渲染：应届生（教育在前、有证件照）、社招（工作在前）、无照片、空模块。
2. 看整页 A4：像不像智联/超级简历上能投的附件；还是像国外花简历。
3. 对照 `05-视觉自审清单.md` 逐条勾。任何一条失败 = 未完成。
4. 编辑器 chrome：白底、细边框、中文、少紫渐变、少 Framer 大动画。参考超级简历编辑器那种「左边表单右边纸」。
5. 导出 PDF 打开后也要看：分页是否切句、照片是否在、文字能否选中（若规格要求可选中）。

不要只截一张图说「渲染出来了」。

## 6. 实现时的仓库事实（避免走错路）

- 应用代码在 `界面/`，npm 命令必须在 `界面/`。
- 路由已是 `HashRouter` + `base: './'`，这对 Electron `loadFile` 是对的。404 和 ErrorBoundary 的 `<a href="/">` 必须改成 `Link to="/"` 或 `navigate('/')`，禁止 `navigate('#/')`（会变成 `#/#/`）。
- 单一 Zustand store：`界面/src/app/store/useResumeStore.ts`，persist key 现为 `resume-storage`。
- 模板入口：`ResumeRenderer.tsx` 的 `templateLoaders` + `TemplateId` + `TemplateModal.tsx`。
- Electron：`electron/main.js`，打包：`node build-setup.js`。**没有** preload、IPC、electron-updater。
- README 还在教用户装 Node 再双击 `启动.bat`；GitHub 已有 v1.0.0 安装包。最终 README 以安装包为主，源码开发为辅。
- 测试：Vitest，目前几乎只有文件名用例。P0 逻辑必须补测试。
- `docs/` 被 gitignore。方案在 `开发方案/`，不要写进被 ignore 的 `docs/`。
